# [Added] — Rede v2: `http_fetch` com redirects, headers e timeout

- ID: 2026-11-15-feat-rede-v2
- Data: 2026-11-15
- Versão: unreleased
- Tipo: Added
- Compatibilidade: Compatível (`http_get` byte-idêntico; `http_fetch` novo, id 43)

## Resumo

`http_fetch(url, opts)` (arity 2): GET com redirects 301/302/303/307/308
(`seguir`/`max_redirecionamentos` 0–10), `timeout` por requisição
(0–60s), `headers` extras e `metodo` (só `GET`). Devolve mapa
`{status, cabecalhos, corpo}` (status final mesmo fora de 2xx).

## Motivação

Fase A5 do plano de sistemas: `http_get` estrito (sem redirect/headers)
trava em qualquer API real; fechar a Fase A antes da persistência.

## O que mudou

- `rhp-bytecode`: variante `HttpFetch`, nome, aridade 2, id 43,
  anti-deriva estendido.
- `rhp-vm/src/builtins.rs`: `FetchOpts` + `parse_fetch_opts` (tudo
  opcional, desconhecida = erro), `do_request` compartilhado,
  `resolve_location` (absoluta/raiz/relativa; `https` = erro),
  `http_fetch_body` (loop com teto de hops); `http_get_body` virou
  wrapper fino do mesmo caminho (mensagens e semântica preservadas).
- Gramática VSCode + teste de consistência.
- Specs: `LANGUAGE_SPEC.md` §6 (tabela), `BYTECODE_SPEC.md` §4 (ids).

## Detalhes técnicos

Sem redirect: `http_get` 3xx segue erro (inalterado). `http_fetch` lê
cabeçalhos em minúsculas, junta duplicados com ", ", descarta corpo de
redirect sem ler (Connection: close), valida header contra injection
(`\r`/`\n`/`:`). Cada resposta respeita o teto de 1 MiB; cada hop conta
no `max_steps` normal (uma instrução por builtin, sem loop infinito).

## Compatibilidade e migração

Compatível. Migração: trocar `http_get` por `http_fetch` onde houver
redirect/headers; `http_get` segue válido para o caso simples.

## Segurança e performance

Sem `unsafe`, sem deps novas, sem TLS (https = erro claro; TLS é Fase D
com ADR). Sem downgrade silencioso. Limites: corpo 1 MiB/resposta, 10
redirects, timeout 60 s.

## Testes e validação

- Falha-antes: builtin inexistente; redirects/headers/timeout sem suporte.
- Servidor HTTP local real (TcpListener, sem rede externa): cadeia
  302→302→200 (absoluta + raiz), eco de header custom, `seguir: false`,
  loop com `max_redirecionamentos: 2`, timeout 1 s vs servidor de 3 s.
- Validação sem servidor em `rhp-vm` (12 casos de opts inválidas + https).
- `cargo test --workspace`: 195 passed, 0 failed (191 antes + 4 novos:
  `rejects_bad_fetch_opts` + 3 de integração com servidor real).
- `cargo fmt --check` ok; `cargo clippy --workspace --all-targets
  -D warnings` ok; `tools/check-changes.sh origin/main` ok.

## Limitações e riscos conhecidos

Só `http://` (sem TLS); sem chunked dedicado (herdado); sem keep-alive;
sem `POST`/outros métodos; sem cookies automáticos; DNS sem timeout
próprio (herdado). Servidor HTTP (lado escuta) é Fase C.
