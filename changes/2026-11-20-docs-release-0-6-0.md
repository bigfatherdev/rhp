# [Docs] — Release 0.6.0: versão, changelog, docs HTTP e baseline de bench

- ID: 2026-11-20-docs-release-0-6-0

- Tipo: Changed (docs + versionamento)

## Resumo

Sincroniza versão `0.6.0` (7 `Cargo.toml` + `Cargo.lock` + `rhp --version`),
adiciona seção `[0.6.0]` ao `CHANGELOG.md`, documenta o HTTP novo
(`WEB.md`, `DOCKER.md`, `REFERENCIA.md`) e normatiza a ordem do operando
de `return` (`LANGUAGE_SPEC.md`, `BYTECODE_SPEC.md`). Registra baseline de
benchmarks 0.6.0.

## Motivação

Missão 0.6.0 §§13–15: docs devem refletir exatamente o runtime; versão
sincronizada em todo o projeto; changelog por Added/Fixed/Improved/
Security/Compatibility/Known limitations.

## O que mudou

- `version = "0.6.0"` nos 7 crates; `Cargo.lock` atualizado; `rhp --version` → `rhp 0.6.0`.
- `CHANGELOG.md`: seção `[0.6.0] — unreleased` (vira data no tag).
- `docs/WEB.md`: seção `http_serve(porta, handler, opts)` + aviso `0.0.0.0`.
- `docs/DOCKER.md`: bind em container + topologia validada; exemplos de tag rolados para 0.6.0.
- `docs/REFERENCIA.md`: `http_serve` (host, 400s, limites, handler-valor) + `return`-em-`try`.
- `README.md`: referências de versão roladas.
- `LANGUAGE_SPEC.md`/`BYTECODE_SPEC.md`: operando de `return`/`yield` avaliado antes de `TryEnd`/`finally`.
- `tools/docker-http-proof.sh` (novo, executável): prova repetível da rede Docker (bind 0.0.0.0, container↔container, nginx reverso, port forwarding, controle negativo); validado 5/5 contra o binário release.

## Segurança e performance

Baseline `bench_rhp` (release, mesma classe de máquina do baseline
2026-11-14): lex 0.8 ms · parse 9.4–10.2 ms · compile 15.0–16.1 ms ·
fib(20) 78–96 ms · while-200k 372 ms · push-20k ~18.6 s. Variação entre
runs (±20–80% em `fib`/`push`) = ruído de CPU compartilhada, não
regressão: nenhum caminho medido foi tocado pelo diff 0.6.0
(lexer/parser/array-push intactos; ver `git diff --stat`). Sem alegações
de ganho; números arquivados como referência futura.
